# Project notes for agents

Deliberate decisions in this repo - do NOT silently revert them:

- `homebrew.onActivation.cleanup = "zap"` in `configuration.nix` is intentional. It forces the good habit of declaring every Homebrew package in the Nix config instead of installing things ad-hoc, which keeps the machine reproducible. Do not soften it to `uninstall` or `none`. Users are warned about its effect in README.md; this note is for anyone tempted to change the setting itself.
- Never commit `.no-mistakes/` validation evidence to this public repo. `.no-mistakes/` is gitignored; if a validation pipeline stages evidence into a branch, drop it before merging.
- Tools with no Homebrew formula and no nixpkgs package are declared via `home.activation` blocks at the end of `home.nix` (see `installNoMistakes`, `cloneFirstmate`, `installAxiTools`, `installPi`, `installMattPocockSkills`), each guarded by a `command -v`/path check so re-running `darwin-rebuild switch` is a no-op. Follow this pattern for future tools in the same situation rather than installing them by hand. `installNoMistakes` additionally reinstalls over the previous fleet pin (the `grep -q "v1.72.0"` old-version guard): the installer always fetches latest and updates are otherwise a manual `no-mistakes update`, so a declared bump converges stale hosts - when bumping the version, move that guard string to the version being replaced.
- opencode is the deliberate exception: it HAS a nixpkgs package and a Homebrew formula, but it is NOT declared in `home.packages`. `home.activation.installOpenCode` installs it to `~/.opencode/bin` via the official v1 installer (`https://opencode.ai/install --no-modify-path --version 1.18.34`, GitHub-release-based), because opencode updates itself from inside the app and a read-only Nix store binary can't be replaced. It is deliberately pinned to the v1 track: use the v1 installer URL (no `/v2` prefix) for 1.x - the v2 installer's `--version 1.x` fallback serves a repackaged payload from the legacy `@opencode-ai` npm scope whose tarball layout doesn't match (`bin/lildax`, not `bin/opencode`), so it fails at the `mv` step. From then on v1 self-updates within the v1 track (latest v1 is 1.18.34; npm `opencode-ai` dist-tag `latest` still tracks it). Do not move it back into `home.packages`; keep the `~/.opencode/bin` entry in `home.sessionPath`. The activation also reinstalls over a v2 binary (v2 self-updates only within its own track), via the `grep -Eq 'v?1\.'` version guard. opencode configs are v1-schema (`provider` singular, `autoupdate`, `npm`/`options` per provider, flat `mcp` map). npm side note: global installs of v1 (the `opencode-ai` meta-package) need `--allow-scripts=opencode-ai` (npm 11 gates the platform-binary postinstall). The `cli.json` next to the config is a v2-only artifact that v1 ignores. no-mistakes review/fix workers deliberately use the separate pinned `opencode-ai@1.18.31` install under `~/.local/share/no-mistakes/`. The `pi` agent CLI (`installPi`, same self-update reason) likewise stays out of `home.packages` despite having a nixpkgs package - it installs via Homebrew's npm like the axi tools.
- OpenSuperWhisper launches at login via the `launchd.user.agents.opensuperwhisper` user LaunchAgent in `configuration.nix` (not the app's own login-item toggle, which would be non-declarative and double-launch it).
- Agent skills (mattpocock pack + any future `skills add -g`) land canonically in `~/.agents/skills/` with per-agent symlinks. `~/.config/opencode` symlinks into this repo, so anything installed under it (e.g. `skills/`) must stay gitignored - vendored blobs must never be committed.
