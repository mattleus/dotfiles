# Project notes for agents

Deliberate decisions in this repo - do NOT silently revert them:

- `homebrew.onActivation.cleanup = "zap"` in `configuration.nix` is intentional. It forces the good habit of declaring every Homebrew package in the Nix config instead of installing things ad-hoc, which keeps the machine reproducible. Do not soften it to `uninstall` or `none`. Users are warned about its effect in README.md; this note is for anyone tempted to change the setting itself.
- Never commit `.no-mistakes/` validation evidence to this public repo. `.no-mistakes/` is gitignored; if a validation pipeline stages evidence into a branch, drop it before merging.
- Tools with no Homebrew formula and no nixpkgs package are declared via `home.activation` blocks at the end of `home.nix` (see `installNoMistakes`, `cloneFirstmate`, `installAxiTools`, `installPi`, `installMattPocockSkills`), each guarded by a `command -v`/path check so re-running `darwin-rebuild switch` is a no-op. Follow this pattern for future tools in the same situation rather than installing them by hand.
- opencode is the deliberate exception: it HAS a nixpkgs package and a Homebrew formula, but it is NOT declared in `home.packages`. `home.activation.installOpenCode` installs it to `~/.opencode/bin` via the official installer (`--no-modify-path`), because opencode updates itself from inside the app and a read-only Nix store binary can't be replaced. Do not move it back into `home.packages`; keep the `~/.opencode/bin` entry in `home.sessionPath`. The `pi` agent CLI (`installPi`, same self-update reason) likewise stays out of `home.packages` despite having a nixpkgs package - it installs via Homebrew's npm like the axi tools.
- OpenSuperWhisper launches at login via the `launchd.user.agents.opensuperwhisper` user LaunchAgent in `configuration.nix` (not the app's own login-item toggle, which would be non-declarative and double-launch it).
- Agent skills (mattpocock pack + any future `skills add -g`) land canonically in `~/.agents/skills/` with per-agent symlinks. `~/.config/opencode` symlinks into this repo, so anything installed under it (e.g. `skills/`) must stay gitignored - vendored blobs must never be committed.
- `pi-box` runs Pi unrestricted in a disposable container on colima's docker VM; `agentbox` (added later, README section) turns the same image into the long-lived fleet workstation: sshd as init (`docker/agent-box/agentbox-init`), subcommands up/ssh/stop/status, secrets from `~/.config/agentbox/env` (gitignored; COHERE_API_KEY required, GH_TOKEN optional pass-through, box ssh keypair beside it). Both scripts (`home/.local/bin/`, linked by home.nix) share image `agent-box:latest` and its `pi-box.dockerfile-sha256` label, which now covers Dockerfile + agentbox-init. Deliberate design: the container's `agent` user is uid 501 with HOME=/Users/matt; only `~/repos`, `~/.pi/agent`, `~/.treehouse` mount in read-write at identical absolute paths and the image symlinks `/Users/matt/firstmate` like the host, so the fleet shares the host fleet home and worktree/session paths resolve unchanged. Never all of `$HOME`. In-box GitHub access is multi-account parity with the host, NOT a PAT: at every `up` the script re-stages host gh accounts (tokens pulled from the login keychain via `gh auth token --user`) into `~/.config/agentbox/gh` mounted read-only over the box's `~/.config/gh`, and copies the host ssh config + named IdentityFiles + known_hosts into the box's own `~/.ssh` (never bind-mounted: those host files are Nix-store symlinks a mount couldn't resolve, and a read-only whole mount would break the box's authorized_keys install). The repo's managed Pi config files must be bind-mounted over `~/.pi/agent` rather than relied on as symlinks, same Nix-store reason (colima's virtiofs shares only /Users/matt). Secrets can't ride docker env into ssh sessions (sshd scrubs it), so agentbox-init rewrites them into agent's `.zshenv` on boot.
